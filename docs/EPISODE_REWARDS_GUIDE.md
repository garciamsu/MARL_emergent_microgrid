# Episode Reward Calculation - Implementation Guide

## Overview

This document describes the **correct implementation** of episode reward calculation in the multi-agent reinforcement learning environment. The implementation follows the standard RL convention where episode rewards are computed independently for each episode.

## Key Principles

### ✅ CORRECT Approach

1. **Episode Reward**: Sum of timestep rewards **WITHIN** the current episode ONLY
2. **Reset**: Episode reward resets to `0.0` at the **START** of each episode
3. **Storage**: ONE value per episode stored in `episode_rewards` list
4. **No Accumulation**: Rewards are **NOT** accumulated across multiple episodes

### ❌ INCORRECT Approaches to Avoid

- Global cumulative sum across all episodes
- Appending timestep rewards directly to plots
- Mixing episodes without proper reset
- Cumulative plots that never reset between episodes

## Implementation Details

### Code Structure

The implementation follows this pattern:

```python
# Initialize storage for episode rewards
episode_rewards = {agent_name: [] for agent_name in agents.keys()}

for episode in range(num_episodes):
    # CRITICAL: Reset episode reward at start
    current_episode_reward = {name: 0.0 for name in agents.keys()}
    
    for timestep in range(max_steps):
        # Compute timestep reward
        timestep_reward = compute_reward(...)
        
        # CRITICAL: Accumulate within episode only
        current_episode_reward[agent_name] += timestep_reward
    
    # CRITICAL: Store episode reward and reset for next episode
    for name in agents.keys():
        episode_rewards[name].append(current_episode_reward[name])
```

### Mathematical Formula

For each episode `e`:

```
episode_reward[e] = Σ(timestep_reward[t]) for t ∈ [0, T-1]
```

where `T` is the number of timesteps in episode `e`.

**Important**: `episode_reward[e]` is independent of `episode_reward[e-1]`.

## Interpreting Results

### Episode Reward Plot

**What it shows**: 
- Each point represents the **total reward** earned in ONE episode
- Values can increase or decrease between episodes
- This shows the TRUE learning curve

**What to look for**:
- **Upward trend**: Agent is improving over time
- **Stabilization**: Agent has converged to a policy
- **High variance**: Environment or policy is stochastic
- **Downward trend**: Potential issues with exploration/exploitation

### Common Mistakes in Interpretation

❌ **WRONG**: "The plot should always increase because rewards accumulate"
- Episode rewards reset each episode; they don't accumulate

✅ **CORRECT**: "The plot shows performance per episode; upward trend indicates learning"

❌ **WRONG**: "Why do rewards go down sometimes?"
- Natural due to stochastic environments and exploration

✅ **CORRECT**: "Fluctuations are normal; look at the moving average for trends"

## Troubleshooting

### Issue: Plot shows constant increase

**Diagnosis**: Likely accumulating across episodes instead of resetting

**Fix**: Verify `current_episode_reward` is reset to `0.0` at start of each episode

### Issue: Rewards don't match manual calculation

**Diagnosis**: Possible mismatch in which rewards are being accumulated

**Fix**: 
- Check that timestep rewards are correctly accumulated
- Verify no rewards are skipped or double-counted
- Ensure initial state (step -1) rewards are handled correctly

### Issue: episode_rewards.csv has wrong number of rows

**Diagnosis**: Appending per-timestep instead of per-episode

**Fix**: Ensure `episode_rewards[name].append()` is called ONCE per episode, not once per timestep
